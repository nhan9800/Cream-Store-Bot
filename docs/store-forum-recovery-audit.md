# Store forum and recovery audit · November 6, 2026

Store1's support channel keeps ID1514607020098191393 and is named **tạo-ticket**. The store category contains the price forum plus the service forum recorded in `storeServiceForum202611.js`. Eleven posts cover the start guide, feedback, honor board, transaction feed, promotions, Valorant, development services, SIM, cards/discounts, events and membership.

`getGuildConfig` resolves current configuration pointers to the new posts; startup persists the same mapping. Historical order/feedback records keep their original message references. Original channels/histories are archived, not deleted. OTP/card/honor/membership and discount workers explicitly use their new posts. Card refresh edits only its own starter and must preserve the discount message in the same post. Promotion/event forum destinations are added to the existing paused-marketing policy.

The live verification defect was an unregistered callback: the bot used `https://api.cenarstore.xyz/oauth/callback` while the application's redirects only included the website host. The owner explicitly approved adding that exact API callback in Developer Portal; existing redirects and credentials were retained. A fresh consent page opened successfully afterward. Completion of a particular user's authorization must still be checked through the real callback; configuration readiness is not equivalent to a working grant.

Public health exposes aggregate member-recovery metadata only: consent/scope/encrypted-credential/expiry counts and the last structure snapshot. Unexpired metadata does not prove a grant has not been revoked. Recovery remains an explicit Admin action for members who granted OAuth `identify guilds.join`; no automatic/bulk join is run during this audit. Credential refresh is bounded to12seconds, validates token/expiry/scope and never reflects provider error bodies. Existing application IDs, encrypted grants, memberships and deferred team ownership remain intact.
